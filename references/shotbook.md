# 内容驱动的 Shotbook

在产品介绍、功能演示和更新报告中读取本页。Shotbook 把内容、真实素材、时间和验收点放在同一张表里，先让每个镜头承担一个清楚的说明任务，再选择版式或动效。

## 时长由内容决定

成片没有固定的默认片长。根据要解释的功能数量、操作链长度、结果细节和观众需要的阅读时间安排章节；目标时长应写进创作简报，不能用一串快速转场替代缺失的功能说明。完整介绍可以从总览进入细节，单项教程可以直接进入一个闭环。

每个功能尽量完成：入口或前状态 → 关键动作 → 可见结果 → 必要细节。只有终态截图时，只能说明终态，不能把它写成完整操作教程；缺少操作前画面、录屏或结果证据时，在素材缺口中明确记录。

先做一段约 20–30 秒、包含主要视觉类型的有声或静音样板镜。样板用于验证信息能否读清、真实素材与字幕是否对齐、动效是否服务语义，不是成片时长限制。样板通过后，按后续段落的新信息扩展；不要把样板动效机械复制到内容不同的后半段。

## 一镜一行

| 字段 | 填写内容 |
| --- | --- |
| 语义锚点 | 对应哪句文案、关键词、功能或操作 |
| 时间 | 起点、终点和使用的时间单位；代码式时间线同时记录帧率 |
| 内容目标 | 说明结论、展示入口、呈现动作、证明结果、补充细节或衔接章节 |
| 真实素材 | 素材路径、截图/录屏/文字类型，以及操作前或操作后状态 |
| 运动用途 | 建立关系、进入细节、强调变化、按顺序展开、比较状态或转入新章节 |
| 停留 | 动作完成后给结果和字幕留下的可读时间 |
| 验收点 | 观众必须看清什么；哪些遮挡、提前显示、错位或空白算失败 |

反馈统一写成：`时间或帧 + 对象 + 实际问题 + 期待变化`。例如：“00:18，结果卡片，点击后过早消失，保留结果并多留一拍让标题读完。”不要只写“更高级”“更有动感”。

## 当前真实录屏与结果高亮接口

真实连续输入、滚动或拖动使用二维录屏，不用两张静态图冒充完整操作。下面是字段结构示意，`rect` 的数值按实际录屏素材填写，不要照抄占位符：

```json
{
  "recording": {
    "source": "assets/real.mp4",
    "trim_start": 0,
    "speed": 1
  },
  "highlights": [
    {
      "rect": [x, y, w, h],
      "start": 3.2,
      "end": 5.4,
      "label": "操作结果",
      "style": "spotlight"
    }
  ]
}
```

`recording` 直接引用真实二维视频，按原速播放、保持完整画面（contain）并强制静音；`trim_start` 从素材中取片段，步骤实际占用时长不能超过裁切点之后的素材剩余时长。`highlights` 可用于单图或录屏，时间相对于当前镜头，`rect` 相对于当前素材，`label` 可省略，`style` 只能是 `outline` 或 `spotlight`。高亮只在可见结果已经出现后开始，不能在动作进行中或结果出现前标注结果。

静态截图的 `images`、原有操作步骤和录屏步骤可以混排。需要结果证据时保留操作前状态、动作过程和结果状态；只有结果图时，降低叙述范围并写出缺少的前状态或动作素材。

## 交付前回看

先看样板和关键帧，再播放最终 MP4。覆盖字幕安全区、操作前后状态、结果驻留、镜头后半段是否出现新信息、章节衔接和成片末尾。`check` / `build` 会输出 `pacing-review.json` 建议，关注字幕密度与留时、动作后的结果驻留、过长静止和缺少前后状态；它只提示问题，不自动改写用户明确的时长。建议仍需结合实际画面、时间线和播放结果判断。
